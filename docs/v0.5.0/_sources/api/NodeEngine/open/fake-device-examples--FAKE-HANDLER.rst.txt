FAKE-HANDLER
============

Library: ``fake-device-examples``

FakeDriver foreground protocol whose local handlers dynamically submit tasks and repeat one stage.

:bdg:`foreground` :bdg:`timeout 30 s`

**Lease:** ``FakeDeviceId``.

1 Required inputs
-----------------

Catalog defaults satisfy the input schema; no input overrides are required.

:doc:`Input defaults and launching </user-guide/running>`.

2 What you get
--------------

.. list-table::
   :header-rows: 1
   :width: 100%
   :class: api-table

   * - Export key
     - Content
   * - ``summary.status``
     - Terminal status returned by the final repeated foreground check.
   * - ``summary.deviceId``
     - FakeDriver device used by the local handlers.
   * - ``summary.gain``
     - Gain submitted by the preparation handler.
   * - ``summary.durationSec``
     - Duration submitted to every foreground check in seconds.
   * - ``summary.iterations``
     - Number of foreground checks executed by the repeat handler.

Declared keys are present after successful completion; values may be null or empty. See :doc:`/user-guide/results`.

   * - Input

   * - ``fakeDeviceId``
     - "FakeDeviceId"
     - length >= 1
     - Identifier of the shared FakeDriver device.
   * - ``gain``
     - 3.3
     - >= 0
     - Synthetic gain set by the local handler.
   * - ``taskDurationSec``
     - 1.0
     - >= 0
     - Duration of each handler-run foreground task in seconds.
   * - ``tickSec``
     - 0.5
     - >= 0
     - FakeDriver task tick interval in seconds.
   * - ``maxIterations``
     - 2
     - >= 1
     - Number of repeat-stage executions.
