Built-in stage handlers
=======================

Built-in stage handlers for submitting and waiting for child protocols, publishing results, running device tasks and registering terminal cleanup.

Handlers receive ``ctx: StageContext`` and ``params: dict`` and normally return ``StageResult``. Decision strings are also accepted; StageResult supports a reason, delay and explicit lease policy. Parameters belong to the stage's ``params`` object, not directly to a run plan.

:doc:`StageContext and StageResult <StageRuntime>` lists signatures, decisions and lease semantics. See :doc:`Writing a meta-protocol </user-guide/writing-meta-protocols>` for complete static and dynamic examples.

**Declared composition:** use :doc:`SubmitMicroProtocolStage <handlers/SubmitMicroProtocolStage>` followed by :doc:`WaitMicroProtocolStage <handlers/WaitMicroProtocolStage>`.

**Runtime composition:** an Open library can bind local Python handlers; see :doc:`FAKE-COMPOSED-SWEEP-BRANCH </api/NodeEngine/open/fake-device-examples--FAKE-COMPOSED-SWEEP-BRANCH>`.
