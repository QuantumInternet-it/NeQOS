Command-line reference
======================

The tables below are generated from the source entry points'
``argparse`` declarations, without importing an engine, loading a driver or
contacting hardware. Defaults are parser defaults: configuration files and
runtime discovery can replace them.

For complete launch sequences, paths and shell syntax, use :doc:`running`,
:doc:`quickstart` and :doc:`installation`. Standalone distributions use the
corresponding executable instead of ``python -m``.

Operating-mode constraints
--------------------------

* NodeEngine requires exactly one of ``--configFile`` and ``--inventoryFile``.
  ``--networkFile`` requires an inventory. A headless ``--metaProtocolRun``
  in inventory mode also requires ``--networkFile``.
* ``--serve`` and ``--metaProtocolRun`` are alternatives; repeatable
  ``--openLibrary`` is available with ``--serve``.
* ``--inventoryDataDir`` is a persistent directory on the NodeEngine host for
  operator history, saved experiments and its database, not an input file.
  Its identity is bound to ``inventoryId`` and device endpoints (IP and
  synchronous-command port), or to the network ID/endpoints in legacy mode.
  Reuse it across experiment networks and executions. Use a separate directory
  for a different identity, not for each run plan. The default is
  ``./inventoryDataDir``, relative to the terminal's working directory;
  this flag does not rename or move existing directories or automatically
  select a different archive for each inventory.
  Point the flag explicitly to an existing ``OperatorData`` archive to
  retain that history after upgrading.
* DeviceOS uses only ``--inventoryFile`` for an ``inventory-1`` document.
  The old ``--configFile`` flag is rejected, and renaming a legacy complete
  network does not convert it. ``--nodeId`` is an optional disambiguation when
  deriving its device configuration.
* DeviceOS command-line identity and transport defaults apply only without
  a shared configuration file. SDK paths belong to ``--localConfigFile``;
  an Open driver registry belongs to ``--openDriversFile``.
* The offline viewer starts neither engine. ``ValidateNetwork`` checks files;
  it does not establish hardware readiness or optical safety.

``DriverContractSource --openDriversFile`` accepts the older
``--open-drivers-file`` spelling as an alias.
