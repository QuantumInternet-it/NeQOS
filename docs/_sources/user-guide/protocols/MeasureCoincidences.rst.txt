MeasureCoincidences
===================

``acquisition.coincidence``

Acquire coincidence counts and rates for selected channel combinations.

:bdg:`foreground` :bdg:`timeout 2 min`

**Lease:** devices selected by ``resourceDeviceIds``.

Acquire finite count-rate observations for AND logical channels formed from two or more input channels.

1 Minimal run
-------------

.. list-table::
   :header-rows: 1
   :width: 100%
   :class: api-table

   * - Input
     - Type
     - Meaning
   * - ``deviceId``
     - string length >= 1
     - TimeTagger device that creates the logical channels and acquires their count-rate measurements.
   * - ``resourceDeviceIds``
     - string[] (items >= 1)
     - Exact lease union: only the TimeTagger when latchGuard is disabled, or that TimeTagger plus every network-resolved detector-health guard when it is required.
   * - ``resourceDeviceIds[]``
     - string length >= 1
     - One device needed by this finite acquisition.
   * - ``observations``
     - object[] (items >= 1)
     - Unique AND-logical coincidence observations acquired together in one finite window.
   * - ``observations[]``
     - object
     - One named logical coincidence definition.
   * - ``observations[].observationId``
     - string length >= 1
     - Caller-stable identifier used as the output-map key.
   * - ``observations[].inputRefs``
     - integer[] (items >= 2)
     - At least two physical TimeTagger channel references joined by AND.
   * - ``observations[].inputRefs[]``
     - integer >= 0
     - One physical TimeTagger channel reference.
   * - ``observations[].coincidenceWindowPs``
     - integer >= 1
     - Coincidence window applied by the AND logical channel, in picoseconds.
   * - ``latchGuard``
     - object
     - Explicit finite-window detector-latch policy; disabled permits an unguarded observation, while required validates network-declared detector-health guards and retries only the invalid window.
   * - ``latchGuard.mode``
     - string "disabled" \| "required"
     - Whether detector-latch validation is disabled or required for this observation.
   * - ``latchGuard.maxWindowRetries``
     - integer >= 0
     - Maximum immediate retries after a recovered detector latch; use zero to reject the first invalid window.

2 What you get
--------------

.. list-table::
   :header-rows: 1
   :width: 100%
   :class: api-table

   * - Export key
     - Content
   * - acquisition.coincidence.\ **observation**\ .window
     - Verified context and raw device response for the completed shared acquisition window.
   * - acquisition.coincidence.\ **plan**\ .definitionsByObservation
     - Resolved stable logical-channel and measurement definitions indexed by observation identifier.
   * - acquisition.coincidence.\ **observation**\ .observationsById
     - Normalized coincidence observations indexed by observation identifier.
   * - acquisition.coincidence.\ **observation**\ .countsByObservation
     - Total coincidence counts indexed by observation identifier.
   * - acquisition.coincidence.\ **observation**\ .countRatesHzByObservation
     - Coincidence rates in hertz indexed by observation identifier.
   * - acquisition.coincidence.\ **status**\ .latchGuard
     - Explicit latch-guard policy, health samples, accepted-window attempt, discarded-window count, and any terminal guard failure.

Every declared key is present after successful completion; its value may be null or empty. Read the keys under ``outputs`` in ``result.json``; see :doc:`/user-guide/results`.

   * - Input
     - Default
     - Allowed
     - Meaning
   * - ``observations[].logicalOperator``
     - not declared
     - "AND"
     - Logical operation used to form the channel.
   * - ``durationSec``
     - 1
     - —
     - Finite integration duration of the shared coincidence observation window, in seconds.
   * - ``clear``
     - true
     - —
     - Whether every selected coincidence measurement is cleared before the window.
