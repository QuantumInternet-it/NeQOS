MeasureLinkSingles
==================

``link.characterization``

Measure guarded singles counts and rates on resolved quantum links.

:bdg:`foreground` :bdg:`timeout 3 min`

**Lease:** no device resources.

Measures finite singles counts and rates for resolved quantum links and returns their acquisition provenance. An explicit latchGuard policy is applied to every acquired window; required includes the network-resolved detector-health devices in the declared resource union.

1 Minimal run
-------------

.. list-table::
   :header-rows: 1
   :width: 100%
   :class: api-table

   * - Input
     - Type
     - Meaning
   * - ``targetLinkIds``
     - string[] (items >= 1)
     - Unique quantum-link identifiers whose TimeTagger sink channels are measured as singles.
   * - ``targetLinkIds[]``
     - string length >= 1
     - One target quantum-link identifier resolved from network.json.
   * - ``latchGuard``
     - object
     - Explicit finite-window latch policy propagated to background and tomography acquisitions. required rejects invalid windows and retries only after detector recovery; disabled deliberately acquires without latch protection.
   * - ``latchGuard.mode``
     - string "disabled" \| "required"
     - Whether per-window detector-latch validation is disabled or required.
   * - ``latchGuard.maxWindowRetries``
     - integer >= 0
     - Maximum immediate retries of an invalid window after a recovered latch.
   * - ``resourceDeviceIds``
     - string[] (items >= 1)
     - Exact acquisition union: TimeTagger plus every network-resolved health guard when required. The acquisition child acquires or inherits these resources.
   * - ``resourceDeviceIds[]``
     - string length >= 1
     - One device needed by this acquisition or scan.

2 What you get
--------------

.. list-table::
   :header-rows: 1
   :width: 100%
   :class: api-table

   * - Export key
     - Content
   * - link.characterization.\ **observation**\ .singles
     - Singles counts and available rates by target link, with resolved TimeTagger channels and acquisition provenance.

Every declared key is present after successful completion; its value may be null or empty. Read the keys under ``outputs`` in ``result.json``; see :doc:`/user-guide/results`.
