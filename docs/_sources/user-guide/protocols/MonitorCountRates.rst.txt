MonitorCountRates
=================

``acquisition.countrate``

Monitor successive count-rate windows and publish their ordered observations.

:bdg:`foreground` :bdg:`timeout 1600 min`

**Lease:** devices selected by ``resourceDeviceIds``.

Acquire a declared number of complete count-rate windows and return the ordered observations with their aggregate summary.

1 Minimal run
-------------

.. list-table::
   :header-rows: 1
   :width: 100%
   :class: api-table

   * - Input
     - Type
     - Meaning
   * - ``deviceId``
     - string length >= 1
     - Device that acquires and continuously reports the requested count-rate measurements.
   * - ``resourceDeviceIds``
     - string[] (items >= 1)
     - Exact lease union: only the TimeTagger when latchGuard is disabled, or that TimeTagger plus every network-resolved detector-health guard when it annotates each monitor window.
   * - ``resourceDeviceIds[]``
     - string length >= 1
     - One device needed by this monitor.
   * - ``channelRefs``
     - integer[] (items >= 1)
     - Unique physical or logical channel references monitored in every acquisition window.
   * - ``channelRefs[]``
     - integer >= 0
     - One channel reference accepted by the acquisition device.
   * - ``latchGuard``
     - object
     - Explicit monitor latch policy; annotate retains an invalid window with health evidence and excludes it from valid aggregate statistics rather than retrying it.
   * - ``latchGuard.mode``
     - string "disabled" \| "annotate"
     - Whether detector-latch monitoring is disabled or each window is annotated.

2 What you get
--------------

.. list-table::
   :header-rows: 1
   :width: 100%
   :class: api-table

   * - Export key
     - Content
   * - acquisition.countrate.\ **observation**\ .windows
     - Ordered normalized observations for every completed count-rate window.
   * - acquisition.countrate.\ **observation**\ .latestWindow
     - Normalized context and raw device response for the final completed window over exactly the requested measurement set.
   * - acquisition.countrate.\ **observation**\ .summaryByMeasurement
     - Per-measurement valid-window count, missing-window count, latch-invalid-window count, accumulated counts, effective capture duration, and duration-weighted aggregate rate.
   * - acquisition.countrate.\ **status**\ .monitor
     - Current monitor status, timing, and completed-window count.

Every declared key is present after successful completion; its value may be null or empty. Read the keys under ``outputs`` in ``result.json``; see :doc:`/user-guide/results`.

3 Options
---------

.. list-table::
   :header-rows: 1
   :width: 100%
   :class: api-table

   * - Input
     - Default
     - Allowed
     - Meaning
   * - ``measurementDurationSec``
     - 1
     - —
     - Integration duration of each acquisition window, in seconds.
   * - ``windowCount``
     - null
     - >= 1
     - Exact number of complete acquisition windows; null continues until the caller aborts the monitor.
   * - ``interWindowDelaySec``
     - 0
     - >= 0
     - Non-blocking delay between completed acquisition windows, in seconds.
