MonitorCountRates
=================

Acquire a declared number of complete count-rate windows and return the ordered observations with their aggregate summary.

Catalog location: ``acquisition.countrate``. This page documents the current exported Reserved contract, not a hardware-test certificate.

Before running
--------------

Read :doc:`../installation`, :doc:`../network` and :doc:`../running`. Start DeviceOS for the devices this run actually uses; a pure numerical protocol needs no hardware process. Explicit lease inputs must agree with the resolved topology.

Outputs and evidence
--------------------

.. list-table::
   :header-rows: 1
   :width: 100%
   :class: api-table

   * - Export key
     - Role / type
     - Meaning
   * - ``acquisition.countrate.observation.windows``
     - observation / array
     - Ordered normalized observations for every completed count-rate window.
   * - ``acquisition.countrate.observation.latestWindow``
     - observation / object
     - Normalized context and raw device response for the final completed window over exactly the requested measurement set.
   * - ``acquisition.countrate.observation.summaryByMeasurement``
     - observation / object
     - Per-measurement valid-window count, missing-window count, latch-invalid-window count, accumulated counts, effective capture duration, and duration-weighted aggregate rate.
   * - ``acquisition.countrate.status.monitor``
     - status / object
     - Current monitor status, timing, and completed-window count. A finite windowCount reaches a terminal result; an unbounded monitor ends through runtime abort and has no terminal result.json.

Read these keys under ``outputs`` in the protocol's ``result.json``. File artifacts and operational state are explained in :doc:`../results`. A declared export is not guaranteed to exist after a crash before publication; inspect the run manifest too.
