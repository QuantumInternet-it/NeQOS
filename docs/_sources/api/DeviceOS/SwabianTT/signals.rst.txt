SwabianTT Signals
=================

.. admonition:: Signal reference
   :class: api-reference

   .. list-table::
      :header-rows: 1
      :width: 100%
      :class: api-table api-signal-table
      :widths: 25 18 15 42

      * - Name
        - Type
        - Unit
        - Description
      * - ``activeMeasurements``
        - ``list``
        - —
        - Measurement references selected for the next StartMeasurement window.
      * - ``deviceInfo``
        - ``object``
        - —
        - Resolved Time Tagger identity and model information.
      * - ``lastMeasurementResults``
        - ``object``
        - —
        - Results returned by the most recently completed StartMeasurement task.
      * - ``logicalChannels``
        - ``list``
        - —
        - Logical channels created during the current measurement-engine session.
      * - ``measurements``
        - ``list``
        - —
        - Measurement definitions created during the current measurement-engine session.
      * - ``physicalChannels``
        - ``list``
        - —
        - Discovered physical channels with live trigger-level and input-delay state.

   .. rubric:: Examples
      :class: examples-heading

   A running micro-protocol must include the target ``deviceId`` in its ``resourceRequests``. NodeEngine retrieves driver capabilities during the device handshake and verifies that the requested signal is advertised.

   Read one advertised signal from a Python handler.

   Replace each ``<...>`` placeholder with the appropriate device ID or advertised signal name.

   .. code-block:: python

      result = await ctx.read_signal(
          deviceId="<device-id>",
          name="<signal-name>",
      )
