Mpc320 Signals
==============

.. admonition:: Signal reference
   :class: api-reference

   .. list-table::
      :header-rows: 1
      :width: 100%
      :class: api-table api-signal-table
      :widths: 25 18 15 42

      * - Name
        - Type
        - Unit
        - Description
      * - ``connection_ok``
        - ``bool``
        - —
        - Result of the driver connection probe.
      * - ``paddle1_position``
        - ``float``
        - ``deg``
        - Current reported position of paddle 1; unavailable when the position read fails.
      * - ``paddle2_position``
        - ``float``
        - ``deg``
        - Current reported position of paddle 2; unavailable when the position read fails.
      * - ``paddle3_position``
        - ``float``
        - ``deg``
        - Current reported position of paddle 3; unavailable when the position read fails.
      * - ``serialNumber``
        - ``str``
        - —
        - Serial number currently resolved by the driver.

   .. rubric:: Examples
      :class: examples-heading

   A running micro-protocol must include the target ``deviceId`` in its ``resourceRequests``. NodeEngine retrieves driver capabilities during the device handshake and verifies that the requested signal is advertised.

   Read one advertised signal from a Python handler.

   Replace each ``<...>`` placeholder with the appropriate device ID or advertised signal name.

   .. code-block:: python

      result = await ctx.read_signal(
          deviceId="<device-id>",
          name="<signal-name>",
      )
