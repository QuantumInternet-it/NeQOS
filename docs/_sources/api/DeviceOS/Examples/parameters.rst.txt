Parameters
==========

Read and write only parameters advertised by the target driver's capability reply.

.. rubric:: Reserve the device
   :class: invocation-heading

The enclosing micro-protocol must reserve the target device.

.. code-block:: json

   {
     "resourceRequests": ["<device-id>"]
   }

NodeEngine retrieves driver capabilities during the device handshake and verifies that the requested parameter is advertised. Use the driver parameter reference to choose a name and valid value.

Replace each ``<...>`` placeholder with an appropriate value.

.. rubric:: Read a parameter from a Python handler
   :class: invocation-heading

.. code-block:: python

   result = await ctx.get_parameter(
       deviceId="<device-id>",
       name="<parameter-name>",
   )

.. rubric:: Write a parameter from a Python handler
   :class: invocation-heading

.. code-block:: python

   result = await ctx.set_parameter(
       deviceId="<device-id>",
       name="<parameter-name>",
       value="<parameter-value>",
   )

.. rubric:: Result
   :class: invocation-heading

``ctx.get_parameter(...)`` returns an envelope with ``deviceId``, ``parameterName``, ``status``, and the device readback in ``value``. ``ctx.set_parameter(...)`` returns the same identifiers plus the requested ``value`` and ``readBack``; the latter is a best-effort readback and may be ``None``.

For either operation, ``status`` describes the NodeEngine-to-DeviceEngine operation. When it is ``ERROR``, ``errorType`` and ``errorMessage`` describe that failure and ``reply`` retains the raw device reply for diagnostics.
