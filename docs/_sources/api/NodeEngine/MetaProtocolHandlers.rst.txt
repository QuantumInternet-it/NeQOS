Meta-protocol Handlers
======================

These compiled handlers implement child microprotocol submission, contract-checked import, result publication, and one declared DeviceOS task invocation.

ExportScratchStage
^^^^^^^^^^^^^^^^^^

Copy selected scratchpad values into the parent protocol exports.

``exports`` is a non-empty list of ``from``/``as`` mappings. Each source
must exist in the current scratchpad. Successful mappings are stored in the
current microprotocol metadata and recorded as an ``ExportScratch`` task
result before the stage advances.

PublishResultStage
^^^^^^^^^^^^^^^^^^

Atomically validate, persist, and publish the declared result contract.

``exports`` is a non-empty list of scratchpad ``from``/contract ``as``
mappings. All values are assembled first, validated against the active
output schema, written as ``result.json`` in the current run directory,
and only then exposed as protocol exports. This keeps disk output and
parent-visible output consistent.

An optional ``failIfScratchPath`` names a scratchpad value that is checked
*after* successful publication. A non-empty value makes the protocol fail
with that value as its reason, while preserving the result artifact and
declared exports for operators and an enclosing parent to inspect.

``writeSummary: true`` additionally writes a shared ``summary.md`` view
beside the canonical result, including a post-publication failure reason.
It introduces no scientific output or protocol-specific sidecar JSON.
The default is false; existing publications remain unchanged.

RegisterTerminalCleanupTaskStage
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Register an idempotent device task for terminal protocol cleanup.

The task is executed by NodeEngine while the lease root is still valid if
the current protocol aborts, fails, or is forcibly released.  It is useful
for a declared child workflow which temporarily opens device-side state
that must be closed before the physical device lease is relinquished.

SubmitMicroProtocolStage
^^^^^^^^^^^^^^^^^^^^^^^^

Submit a child microprotocol and retain its runtime ID in scratchpad.

``templateId`` is required; ``protocolKey`` selects the scratchpad key
``_mp_<protocolKey>`` and defaults to the template ID. Optional shared,
common-stage, stage-specific, resource, and scratch-import overrides are
validated before submission. Shared references are resolved before the
child is submitted, then the stage advances.

WaitMicroProtocolStage
^^^^^^^^^^^^^^^^^^^^^^

Wait for a child runtime submitted under a protocol key.

The handler reads the runtime ID saved by ``SubmitMicroProtocolStage``. It
requeues while the child is active, advances when it succeeds, and fails
when it reaches a failed or aborted state. On success, optional ``imports``
copy declared child exports into the parent scratchpad. ``pollDelaySec``
controls the requeue delay and defaults to 2 seconds.
